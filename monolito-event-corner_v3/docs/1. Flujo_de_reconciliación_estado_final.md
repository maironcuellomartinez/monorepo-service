  Flujo de reconciliación — estado final

  Incidencia creada
         │
         ▼
  OutboxWorkerService (cada 5s)
    → IncidentServiceNowHandler
    → createIncidentTicket → snowq
         │
     ┌───┴──────────────┐
     │ ÉXITO inmediato  │  → servicenow_id + number guardados ✓
     │                  │
     │ ÉXITO async      │  → snowq_correlation_id guardado
     │                  │        │
     │                  │        ▼
     │                  │  MonolithReconcilerJob (cada 30s)
     │                  │  → cuando snowq reporta DELIVERED → persiste ids ✓
     │                  │  → cuando snowq reporta FAILED → limpia correlationId
     │                  │                                       │
     │ FALLO total      │ ──────────────────────────────────────┘
     │ (3 reintentos    │
     │  agotados)       │       → incidencia HUÉRFANA (ni id ni correlationId)
     └──────────────────┘                │
                                         ▼
                                SnowOrphanRecoveryJob (cada 10 min) ← NUEVO
                                → busca incidencias no terminales sin ambos campos
                                → reintenta createIncidentTicket directamente
                                → si SN sigue caído: logea y reintenta en el
                                  próximo ciclo (indefinidamente hasta que SN vuelva)

  Variables de entorno para activar

  En apps/monolith/.env.development y .env.staging:

  # Activar recuperación de huérfanas (false en dev, true en staging/prod)
  SNOW_ORPHAN_RECOVERY_ENABLED=true

  # Intervalo entre ejecuciones en segundos (default: 600 = 10 min)
  SNOW_ORPHAN_RECOVERY_INTERVAL=600

  # Solo procesar incidencias creadas hace más de N minutos (evita colisión con flujo normal)
  SNOW_ORPHAN_MIN_AGE_MINUTES=10

  En dev queda desactivado por defecto para no interferir durante el desarrollo.
