---
  Cambios en api-snowq-service

  request-priority.enum.ts — Backoff exponencial:
  Antes:  intento 1→30s, intento 2→30s, intento 3→30s  →  FAILED en ~90s
  Ahora:  intento 1→30s, intento 2→60s, intento 3→120s, ... techo 10min
  Si SN vuelve después de 2 minutos, el intento 3 ya tiene 120s de espera → mayor probabilidad de que SN esté disponible cuando snowq reintente.

  snow-request.entity.ts — maxRetries: 10:
  Con el backoff exponencial, 10 intentos para MEDIUM cubren hasta ~53 minutos de caída de SN antes de pasar a FAILED. Antes con 3 intentos planos solo cubría 90 segundos.

  snow-request-queue.controller.ts — lastError en el status:
  El reconciler ahora puede saber si el fallo fue por auth rota o por SN caído.
