```txt
 Cómo se relaciona el usuario con su dispositivo en Minerva

  La relación es directa por campo en la tabla devices — no hay tabla de join. Cada dispositivo tiene:

  devices
    ├── serialNumber  (unique)
    ├── usuarioId     ← ID del usuario en el monolith (string libre, nullable)
    ├── usuarioNombre ← nombre display del usuario (nullable)
    └── tipo, marca, modelo, nombre, descripcion

  Flujo de sync:
  UI → POST /api/devices/sync-user/:userId (api-gateway)
     → POST /internal/devices/sync-for-user/:userId (monolith)
     → integration-service → MinervaSoapClient.getDevicesByUser(userId)
     → Minerva filtra por usuarioId = :userId
     → monolith upsertea en su tabla local devices (assigned_user_id = userId)

  El usuarioId en Minerva debe coincidir exactamente con el monolithUserId del usuario (el UUID del monolith, que es lo que usa el
  sync-for-user endpoint).
```

```ts
  curls para testing

  Minerva expone REST en :3015 y SOAP en :3016. Usá el REST que es más simple:

  1. Crear un dispositivo sin asignar

  curl -X POST http://localhost:3015/api/devices \
    -H "Content-Type: application/json" \
    -d '{
      "nombre": "Laptop Dell Latitude",
      "serialNumber": "SN-DELL-001",
      "tipo": "LAPTOP",
      "marca": "Dell",
      "modelo": "Latitude 5520"
    }'

  2. Crear un dispositivo ya asignado a un usuario:

  Reemplazá <monolithUserId> con el UUID del usuario en el monolith:
  curl -X POST http://localhost:3015/api/devices \
    -H "Content-Type: application/json" \
    -d '{
      "nombre": "Laptop HP EliteBook",
      "serialNumber": "SN-HP-002",
      "tipo": "LAPTOP",
      "marca": "HP",
      "modelo": "EliteBook 840",
      "usuarioId": "<monolithUserId>",
      "usuarioNombre": "Juan Perez"
    }'

  3. Asignar un dispositivo existente a un usuario (via SOAP REST)

  curl -X POST http://localhost:3015/api/devices \
    -H "Content-Type: application/json" \
    -d '{
      "nombre": "iPhone 14",
      "serialNumber": "SN-IPHONE-003",
      "tipo": "MOBILE",
      "marca": "Apple",
      "modelo": "iPhone 14",
      "usuarioId": "<monolithUserId>",
      "usuarioNombre": "Juan Perez"
    }'
```

```ts
  TOKEN=$(curl -s -X POST http://localhost:3000/api/auth/login \
    -H "Content-Type: application/json" \
    -d '{"email":"admin@eventcorner.com","password":"<pwd>"}' | jq -r '.token')

  curl -X POST http://localhost:3000/api/devices/sync-user/<monolithUserId> \
    -H "Authorization: Bearer $TOKEN"

```

```ts
  Para obtener el monolithUserId de un usuario:
  curl http://localhost:3000/api/auth/me \
    -H "Authorization: Bearer $TOKEN"
  # → campo "monolithUserId"

  O desde el admin panel: GET /api/admin/users lista todos con su id (que es el monolithUserId).
```
