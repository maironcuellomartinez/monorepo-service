## Helmet

Protege contra vulnerabilidades HTTP comunes:

- XSS (Cross-Site Scripting)
- Clickjacking (X-Frame-Options)
- MIME sniffing (X-Content-Type-Options)
- Otros encabezados de seguridad

Se aplica globalmente en `main.ts`:

```typescript
app.use(helmet());
```

---

## CORS

Configuracion dinamica segun entorno:

```typescript
const corsOrigins = env === 'development'
  ? ['http://localhost:5173', 'http://localhost:3000']
  : process.env.CORS_ALLOWED_ORIGINS?.split(',').map(o => o.trim()).filter(Boolean) ?? [];
app.enableCors({ origin: corsOrigins, credentials: true });
```

- **Development**: origenes fijos (localhost:5173 para el dashboard, localhost:3000)
- **Staging/Production**: solo los definidos en `CORS_ALLOWED_ORIGINS`
- **Sin wildcard**: no se permite `*` en ningun entorno

## Validacion de entorno

La funcion `requiredSecret()` en `configuration.ts` protege contra configuraciones inseguras:

```typescript
function requiredSecret(key: string, fallback: string): string {
  const env = process.env.NODE_ENV ?? 'development';
  const value = process.env[key];

  if (env !== 'development') {
    if (!value) throw new Error(`Variable '${key}' no configurada`);
    if (value.startsWith('dev-only--')) throw new Error(`Variable '${key}' tiene valor de desarrollo`);
    return value;
  }

  return value ?? fallback;
}
```

Variables protegidas: `JWT_SECRET`, `ADMIN_SESSION_SECRET`, `ABAC_M2M_TOKEN`.

En staging/production, si alguna de estas variables falta o tiene el valor de desarrollo (`dev-only--...`), el servicio **no arranca**.

## Sesion de administrador

La sesion del dashboard se maneja con cookie httpOnly:

```typescript
res.cookie('admin_session', token, {
  httpOnly: true,
  sameSite: 'strict',
  path: '/',
  secure: env !== 'development',  // solo HTTPS en prod
  maxAge: 24 * 60 * 60 * 1000,   // 24h
});
```

- **httpOnly**: no accesible desde JavaScript — inmune a XSS
- **sameSite: strict**: no se envia en requests cross-site — inmune a CSRF
- **secure**: solo en HTTPS (excepto development)
- **maxAge**: 24 horas

## Guards de autenticacion

### AccessTokenGuard

Valida el JWT de cliente externo en endpoints de datos:

```typescript
const payload = this.jwt.verify(token, { secret });
if (payload.type !== 'external_client') {
  throw new UnauthorizedException('Token no pertenece a una aplicacion externa');
}
```

### AdminSessionGuard

Valida la cookie de sesion de administrador en endpoints de gestion:

```typescript
const payload = this.jwtService.verify(token);
(request as any).adminUser = { username: payload.username };
```

### AdminOrAccessGuard

Guard compuesto que acepta ambos metodos (usado en `/v1/requests/*`):

1. Intenta cookie de admin
2. Si falla, intenta Bearer token de cliente externo
3. Si ninguno es valido → 401

### OAuthBulkheadGuard

Protege `POST /oauth/token` contra fuerza bruta y DoS via bcrypt. Ver la seccion [Resiliencia](/docs/resiliencia) para detalles.

## Rate limiting

```typescript
// Global
ThrottlerModule.forRoot([{
  name: 'global',
  ttl: 60000,
  limit: 100,
}])

// Endpoints especificos
@Throttle({ default: { limit: 10, ttl: 60000 } })  // /oauth/token
@Throttle({ default: { limit: 5, ttl: 60000 } })   // /oauth/refresh
@Throttle({ default: { limit: 5, ttl: 60000 } })   // /admin/login
```

## Validacion de input

```typescript
app.useGlobalPipes(new ValidationPipe({
  whitelist: true,              // elimina propiedades no declaradas en DTO
  forbidNonWhitelisted: true,   // lanza error si envian propiedades extra
  transform: true,              // transforma tipos (string -> number, etc.)
}));
```

## TypeORM synchronize

```typescript
synchronize: config.get('app.env') === 'development',
```

`synchronize: true` solo en development. En staging y production se usa `false` y las migraciones se ejecutan manualmente para evitar cambios de esquema no intencionados.
